Tiny Engineer · 多人接入手册

怎么让别人（以及别人的 Claude / Codex / Cursor / Gemini）用上你这台机器人；以及"多人混用"到底会不会出问题、出什么问题。下面的命令都在本机对你的机器人实测过。

机器人 192.168.70.196 固件 main-261adc2 WiFi WX-newst /anim 可用 /play 可用 access_token 未设置 CLI tiny-engineer 0.3.0

00先说结论

  1. 机器人端什么都不用装。它是一个只认 HTTP 的小服务器。要装的是每个人自己电脑上的钩子（Cursor / Claude Code / Antigravity 各有一个配置文件），指向同一个 IP 即可。你的机器人已经在局域网里，别人不需要你的仓库、不需要你的电脑。
  2. 现在这台是"谁都能开"的状态。/auth 返回 required:false，同一网段任何人可以驱动它，也可以 POST /settings/reset 把它从网络上抹掉（之后只能物理重配）。多人之前，先设口令。
  3. 同一台同时给 4 个人用，会出问题，但不是"崩"，是"变得没意义"。固件是单线程、无会话、只保留最新一次切换（/anim 最新者胜，每次至少保持 1 秒）。两个 agent 同时发姿态 → 机器人来回抽搐，且分不清是谁的回合响铃。
  4. 正解取决于你的 5 台批量：一人一台。每台改 hostname 和口令，各人指各人的 IP。共享一台只适合"围观/演示"，或者加一层网关（第 8 节，已经写好并跑通 21 项测试）。
  5. 一件必须知道的事：这台已刷到 v0.2.0-28-g261adc2（上游 main）：POST /play 可用，WiFi 记录也从 1 个变成 5 个。

02三分钟接入（按 agent 分）

官方 CLI 覆盖 Cursor / Claude Code / Antigravity，一条 setup 就把钩子写进项目、把地址和口令写进用户级配置。Codex 和 Gemini CLI 官方没做集成，得手写配置——下面给的是它们各自的官方钩子机制。

Agent写在哪个文件命令 / 配置映射到的事件 · 限制
Cursor .cursor/hooks.json
（项目级）		 npx -y tiny-engineer setup cursor --yes --url http://192.168.70.196 11 个事件全映射：会话开始/提交提示/读文件 → reading，思考/压缩 → thinking，改文件/跑命令/子 agent → typing，回合结束 → ring，中断 → abort，失败 → error。需在 Cursor 设置里打开 Hooks。
Claude Code .claude/settings.json npx -y tiny-engineer setup claude-code --yes --url http://192.168.70.196 同上（PreToolUse / PostToolUse / Notification / Stop 等）。
Antigravity .agents/hooks.json npx -y tiny-engineer setup antigravity --yes --url http://192.168.70.196 同上；它的钩子要往 stdout 回 decision JSON，CLI 已处理。
Codex ~/.codex/config.toml
（用户级，根键）		 见下方 TOML 只有 agent-turn-complete 一个事件 → 只能在回合结束时 ring，没有 typing/reading/thinking 的中间过程。
Gemini CLI .gemini/settings.json
（项目或用户级）		 见下方 JSON BeforeTool/AfterTool → typing，BeforeAgent → reading，AfterAgent → ring。部分版本钩子默认关闭。
Windsurf / 其他 / CI 你自己的脚本 curl --noproxy '*' -m 2 -X POST "http://192.168.70.196/anim?name=typing" || true 只有 name 一个参数；2 秒超时 + 忽略错误，机器人离线时不会卡住 agent。

Codex：只有一个"回合结束"铃

Codex 的 notify 是 根级键，必须写在任何 [table] 之前；触发时把一段 JSON 作为一个额外参数追加在你的命令后面，所以要用 sh -c 吃掉它。

# ~/.codex/config.toml —— 根键必须写在各 [table] 之前
notify = ["sh", "-c", "curl -s -m 2 -X POST 'http://192.168.70.196/anim?name=ring' >/dev/null 2>&1", "sh"]

Windows 上把 "sh" 换成 "C:\\Program Files\\Git\\bin\\bash.exe"，或用 ["cmd","/c","curl -s -m 2 -X POST \"http://192.168.70.196/anim?name=ring\" >nul 2>&1"]。

Gemini CLI：钩子写在 settings.json

结构是 hooks.<事件> → 数组，元素带 matcher 和 hooks[]；matcher 在工具事件里是正则（工具名是 run_shell_command / write_file 这种蛇形名）。

{
  "hooks": {
    "BeforeAgent": [{ "hooks": [{ "type": "command", "command": "curl -s -m 2 -X POST 'http://192.168.70.196/anim?name=reading' >/dev/null 2>&1", "timeout": 5000 }] }],
    "BeforeTool":  [{ "matcher": "write_.*|replace|run_shell_command",
                     "hooks": [{ "type": "command", "command": "curl -s -m 2 -X POST 'http://192.168.70.196/anim?name=typing' >/dev/null 2>&1", "timeout": 5000 }] }],
    "AfterAgent":  [{ "hooks": [{ "type": "command", "command": "curl -s -m 2 -X POST 'http://192.168.70.196/anim?name=ring' >/dev/null 2>&1", "timeout": 5000 }] }]
  }
}
Gemini 的两个坑① 钩子必须不往 stdout 写字（除最终 JSON），所以命令里 >/dev/null 不能省，否则 Gemini 会把输出当决策解析。② 部分版本默认禁用钩子：跑起来后进 /hooks 面板确认这三条已注册，没有就在顶层加 "hooksConfig": {"enabled": true}。

05访问口令：多人之前必须先做

当前 GET /auth → {"required":false}。这意味着同一网段任何人（包括访客、演示时投屏的同事、随手写的脚本）都能：改音量/睡眠时间、把机器人从 WiFi 上抹掉、让五个舵机全速来回甩。设一个口令就都挡住了。

# 设口令（会立即生效，之后所有 JSON 接口都要 Bearer）
curl --noproxy '*' -X POST http://192.168.70.196/settings \
  -H 'Content-Type: application/json' -d '{"access_token":"te-desk-2026"}'

# 确认
curl --noproxy '*' http://192.168.70.196/auth        # required 变 true

# 客户端带上它（CLI 会写进用户级配置，之后所有项目共用）
npx -y tiny-engineer setup --all --yes --url http://192.168.70.196 --token te-desk-2026
限制说明
只有一个共享口令没有按人/按 agent 区分的令牌，也没有速率限制和审计。谁拿到都能全权操作，撤权只能换口令让所有人重配。
HTML 面板仍公开页面能打开，但它在浏览器里会先弹口令框；JSON 接口才是硬门槛。
口令别写进 Git 仓库用 --token 进用户级配置（%APPDATA%\tiny-engineer\env / ~/.config/tiny-engineer/env），或系统环境变量 TINY_ENGINEER_TOKEN。

06多人混用：真实会发生什么

不是"并发崩溃"，是语义崩塌。全部来自固件行为，不是猜测：

症状机制多人场景下的后果对策
机器人来回抽搐无队列，/anim 最新者胜，每个姿态至少保持 1 秒A 的 typing 和 B 的 reading 每秒互相顶掉，看起来像坏了一人一台；或网关的"租约"（第 8 节）
铃响了，但不是你ring 是一段约 2 秒的一次性动作，可被下一个请求打断，结束后回 none"回合结束"这个唯一有用的信号失去意义一人一台；或按人分铃声/分机器人
姿态莫名持续 5 分钟连续姿态 continuous_timeout（默认 5 分钟）超时转 attention；同名重复 POST 会续命别人一直 typing，你的 reading 到期被拽去 attention 举手按人拆开；或网关丢弃非持有者的姿态
说话时所有人卡住WebServer 单线程，/play 占住连接直到音频结束一个人放 30 秒语音，其他人的钩子全部超时网关加"说话锁"；或干脆不给多人开 /play
机器人被"弄掉线"POST /settings/reset 清 WiFi，之后只能进 setup AP 物理重配一个人手滑，全组的机器人下线设口令 + 网关把这类路由锁成 admin only
舵机被猛甩/test/movement 让五个关节依次走 +0.5 → −0.5有人正在调机构/上螺丝时被别处触发同上；物理上也别把机器人当公共玩具
5 台互相打架出厂 hostname 都是 tiny-engineer → tiny-engineer.local 撞名谁的 .local 都可能是别人那台每台改 hostname（第 9 节）

07三种组织方式

方案 A · 一人一台 推荐

正好是你在做的 5 台批量。零额外软件，零争抢。

  • 每台唯一 hostname（te-01 … te-05）
  • 每台独立口令（或干脆不设，因为是私有）
  • 每人 --url http://192.168.70.1X
  • 路由器上做 5 条 DHCP 静态绑定

代价：5 倍硬件成本；好处：每人一个专属"身体"，语义完整。

方案 C · 一台共享，只当"公共铃" 最低成本

给整个组一个"有人干完了"的物理提示。

  • 只保留 ring / attention / error
  • 关掉 typing/reading/thinking（钩子里改映射，或让网关丢弃）
  • 不要开 /play

代价：没有"我在这干活"的陪伴感；好处：不会抽搐，冲突面最小。

方案 B · 一台共享，中间加网关 已实现

一台机器一台机器人，但用约 400 行 Node（无依赖）把并发翻译成排队。别人只改一个地址，其余客户端不用动。

  • 租约：连续姿态（typing/reading/thinking/talking）同时只有一个"持有者"，别人收到 409 busy——钩子本来就忽略错误，所以别人的 agent 不会被拖住，机器人也不会抽搐
  • 抢占：ring/attention/error/abort/dead 永远放行；约 2.6 秒后自动把持有者的姿态接回去
  • 去重：同人同姿态 1.2 秒内只发一次（对齐固件 1 秒最小保持）
  • 说话锁：/play 同时只允许一条流，其余 409 + Retry-After
  • 护栏：/settings、/settings/reset、/test/*、/setup/* 需要 X-Admin-Key，普通人只能动姿态
  • 面板：http://网关:8080/ 看谁在驾驶、每人次数、最近 20 条事件

09五台批量：命名与配置

出厂都是 tiny-engineer，五台同网必然撞名。先改名再配网，改名需要重启才生效。

# 对每一台（先连它当前的 IP）
IP=192.168.70.196
NAME=te-01
TOKEN=te-01-<随机串>

curl --noproxy '*' -X POST "http://$IP/settings" -H 'Content-Type: application/json' \
  -d "{\"hostname\":\"$NAME\",\"access_token\":\"$TOKEN\"}"

# 断电重启后，它会以 $NAME.local 出现（建议直接用 IP 或静态绑定）
curl --noproxy '*' "http://$IP/auth"      # 确认 required:true
机器hostname静态 IP（示例）归属
1te-01192.168.70.201你自己（主力）
2–5te-02…te-05.202….205同事各一台
v0.2.0 只存一个 WiFi你现在这台 /settings 返回的是 wifi_ssid（单数）。仓库 HEAD 已经支持 5 个网络（扫描后按信号强弱挑），但要刷新固件才生效。在公司/家里两边用之前，先刷固件，否则每次换地方都要重配。
